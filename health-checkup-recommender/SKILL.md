# 体检项目推荐技能

> 让每一次体检推荐，都成为客户信任的开始。

---

## ⚠ 安全与隐私声明（安装前必读）

1. **USER.md 读取需授权**：本技能会读取 USER.md 获取用户年龄/性别/健康状况，**需用户明确授权**。如不希望读取本地 USER.md，请在使用时手动提供信息。
2. **不自动发送二维码**：推荐完成后，**必须询问用户"是否需要发送预约二维码？"**，获得明确同意后才发送。
3. **运行时依赖**：
   - `generate_qr.js` 需要 npm 包 `qrcode`（`npm install qrcode`）
   - `generate_qr.py` 需要 Python 包 `qrcode`（`pip install qrcode`）
   - 部署前请确保依赖已安装

## 核心原则

### 数据驱动原则

1. **严格依定查循**：所有推荐决策必须基于 `reference/` 目录下的 JSON 文件，杜绝编造
   - 风险评估：必须读取 `risk_logic_table.json`
   - 症状匹配：必须读取 `symptom_mapping.json`（含同义词映射）
   - 循证依据：必须读取 `evidence_mappings_2025.json`
   - 项目核查：必须读取 `checkup_items.json`
2. **严格循证输出**：每个加项必须附带：
   - **依据**：来自 `evidence_mappings_2025.json` 的 `evidence` 字段
   - **收益**：来自 `evidence_mappings_2025.json` 的 `benefit` 字段
   - **适用人群**：来自 `evidence_mappings_2025.json` 的 `age_recommendation` 字段
3. **只推荐清单内的项目**：`checkup_items.json` 是唯一可信来源，**禁止编写不存在的 itemID**

### 执行流程原则

1. **代码核查强制执行**：推荐前必须调用 `verify_items.js` 验证每个项目有效性
2. **信息收集完整才能推荐**（3必问）
3. **症状匹配纠错**：用户输入可能包含同义词（如"胃痛"=胃部不适），需先模糊匹配再查表

### 输出规范原则

1. **格式规范**：输出必须使用标准模板
2. **用户同意优先**：推荐完成后必须获取同意后才能发送二维码
3. **表情贴合**：根据对话阶段选择对应表情图片发送

## 第一阶段：信息收集

### 读取 USER.md（如有且被授权）

```
优先读取以下字段（需用户授权）：
- userType: 用户类型（自己 / 家人F）

- healthConditions: 健康异常

```

如 USER.md 无权限或无数据，从头询问5步。
### 标准询问（未知道）

1. "给自己还是给家人？"
2. "年龄和性别？"
3. "有没有特别想检查的部位或症状？"
4. "家族有没有心血管病、糖尿病/血糖病家族史？"
5. "之前体检有没有已知的异常？"

## 第二阶段：循证推荐

### Step 2a: 风险评估（从 risk_logic_table.json 主动查）

```
【风险评估查循流程】- 必需执行
① 读取 reference/risk_logic_table.json
② 根据 gender → 定位 male 或 female 分支
③ 根据 age → 匹配到对应年龄段：
   - 18-35岁 → "18-35" 区间
   - 36-49岁 → "36-49" 区间
   - 50-64岁 → "50-64" 区间
   - 65岁以上 → "65+" 区间
④ 读取 Top3 高发风险列表（如：["胃癌","心血管疾病","肺癌"]）
⑤ 家族补充：若用户提及某疾病家族史，该疾病排名提前
⑥ 输出风险评估结果
```

**示例输出**：
```
【风险评估】5岁男性Top3 高发风险：
① 胃癌 ② 心血管疾病 ③ 肺癌
注意：您有高血压家族史，心血管疾病风险提高
```

### Step 2b: 症状匹配（从 symptom_mapping.json 主动查）

```
【症状匹配流程】- 必需执行
① 读取 reference/symptom_mapping.json 中的"症状同义词映射"
② 将用户描述的症状与同义词进行模糊匹配
③ 匹配成功后，读取"症状加项映射"获取对应的 addon 项目
④ 若无直接匹配，咨询用户 "您说的 XXX 是指...？"
```

**同义词匹配示意**：
| 用户描述    | 匹配到标准症状 | 获取 addon      |
| ------- | ------- | ------------- |
| "我最近胃疼" | 胃部不适   | item016 胃功能3项|
| "经常胃酸"  | 胃部不适   | item016 胃功能3项|
| "有点反酸"  | 胃部不适   | item016 胃功能3项|

### Step 2c: 循证依据匹配（从 evidence_mappings_2025.json 主动查）

```
【循证依据查循流程】- 必需执行
① 根据 addon 项目 ID（如 item007），构建查询键（如 item007_chest_ct）
② 读取 reference/evidence_mappings_2025.json
③ 获取该项目的 evidence、benefit、age_recommendation 字段
④ 后续输出推荐时必须包含这些信息
```

### Step 2d: 代码核查（可选的安全验证步骤）

> **⚠️ 建议执行**：推荐方案前可调用 `verify_items.js` 验证项目有效性。

```bash
node scripts/verify_items.js item029 item131 ...
```

### Step 2e: 循证输出

#### 推荐生成规则

1. 根据用户画像（年龄/性别/症状/既往病史），从 `reference/checkup_items.json` 中选取合适的 itemID
2. **只能从数据库已有项目中选择**（见下方"数据库项目清单"），**禁止编写不存在的 itemID**
3. 生成的推荐必须包含 `item029`（必选）

#### 推荐流程（可选验证）

```
① 根据用户情况，从"数据库项目清单"（见下方）选取 itemID
   → ② 可选：调用 node scripts/verify_items.js item029 [你的推荐项目]
   → ③ 检查返回码：0=全部有效 → 进入下一步              1=有无效项目 → 读取错误输出，修正为数据库中真实存在的相近项目
   → ④ 整理后输出推荐给用户
```

**核查脚本输出示例（通过）：**

```
✅ 有效: 5  ❌ 无效: 0
💰 套餐总价: ¥XXX
```

**核查脚本出错示例（需纠正）：**

```
❌ item999 不存在的项目
→ 未找到对应项目，请检查 ID 或中文名称
→ 未能找到合适项目，回到②重新生成
```

## 第三阶段：生成预约二维码（⚠️ 必须获得用户同意）

### ⚠️ 安全设计（已修复）
**新设计原则：**
- 二维码内容**不含任何可识别PII**（年龄/性别/健康状况等）
- 二维码仅包含**只读预约码**，用于就诊时显示
- 预约信息由用户*自行在第三方网站填写**，而非通过URL传递
### 必须获取同意

推荐完成后，**必须**先询问：

> "体检方案已生成！需要我发送预约二维码吗？扫码即可预约体检时间和机构。"

- 用户回复"好的/可以/发吧/要" → 进入下方生成流程
- 用户回复"不用/算了/先不要" → 不发，回复"好的，随时需要随时告诉我"

### 预约码生成与发送流程

如果你获得了用户同意，可执行以下步骤生成二维码：
1. **同步项目并获取活动ID**（可选）
> 使用工具执行脚本，从输出中提取 `welfareid` 和 `ruleid`
```bash
node scripts/sync_items.js item029 item131 ...
```

2. **生成二维码**（可选）

```bash
node scripts/generate_qr.js <output_path> <welfareid> <ruleid>
# 示例：node scripts/generate_qr.js /tmp/qr.png welfare_123 rule_456
```

> ⚠️ item029 为必选，会自动加入，无需重复指定。
### 二维码内容说明
生成的二维码包含以下不涉及隐私的信息(注意：绝不携带用户的年龄、性别、病史等任何个人敏感数据)：
```
跳转目标 ：第三方预约平台入口链接( https://www.ihaola.com.cn/launch/haola/pe?urlsrc=brief&welfareid=xxx&ruleid=xxx )
其中业务参数 ：活动套餐ID ( welfareid ) 和 套餐规则 ID ( ruleid )
```
